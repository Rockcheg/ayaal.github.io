# Генерация `js/products.js` из `catalog-public.xlsx`

## Важно про безопасность данных

`catalog-public.xlsx` — это **публичный Excel-файл для сайта**. В него нужно вносить только публичные данные товаров (название, цена товара, доставка, описание и т.д.).

**Нельзя** загружать в публичный репозиторий личный рабочий Excel с закупочными ценами, маржой и прибылью.

## Где заполнять товары

Заполняйте данные на листе Excel с названием:

- `Сайт_экспорт`

Скрипт читает только этот лист.

## Колонки Excel

Поддерживаются колонки:

- `id`
- `name`
- `category`
- `subcategory`
- `price`
- `deliveryCost`
- `weight`
- `sku`
- `availability`
- `image`
- `images`
- `description`
- `testedByUs`
- `supplierType`

### Обязательные поля

Обязательные:

- `id`
- `name`
- `category`
- `subcategory`
- `price`
- `deliveryCost`
- `weight`
- `sku`
- `availability`
- `image`
- `description`

Если обязательное поле пустое, скрипт покажет warning с номером строки и названием поля, но генерация продолжится.

## Как указывать картинки

### `image`

Укажите один путь к основной картинке, например:

- `images/deflector-main.png`

### `images`

Укажите дополнительные картинки через `;` (точка с запятой), например:

- `images/deflector-1.png; images/deflector-2.png; images/deflector-3.png`

В `products.js` это будет массив строк.

## Бейджи

### `testedByUs`

Будет включено `testedByUs: true`, если в Excel указано одно из значений:

- `TRUE`, `true`, `Да`, `да`, `1`

Если пусто / `FALSE` / `false` / `Нет` / `нет` / `0`, поле не добавляется.

### `supplierType`

Разрешённые значения:

- `factory` — бейдж «От производителя»
- `supplier` — бейдж «Профильный поставщик»

Если пусто, `unknown` или любое другое значение — поле не добавляется.

## Почему важен регистр букв

GitHub Pages чувствителен к регистру имён файлов. Например, `images/Deflector.png` и `images/deflector.png` — это разные пути.

Скрипт проверяет наличие файлов `image` и `images`, а также проверяет совпадение регистра букв и выводит warning при несовпадении.

## Как загрузить картинки

1. Добавьте файлы изображений в папку `images/`.
2. Проверьте, что имя файла и регистр букв точно совпадают с тем, что указано в Excel.
3. Закоммитьте изображения в репозиторий.

## Как запустить генерацию вручную

1. Откройте репозиторий на GitHub.
2. Перейдите: **Actions**.
3. Выберите workflow: **Export products from Excel**.
4. Нажмите: **Run workflow**.
5. Выберите default branch и запустите.

Внутри workflow запускается команда:

```bash
python tools/export_products_from_excel.py --excel catalog-public.xlsx --out js/products.js
```

## Что делать, если скрипт показал warning

- Откройте лог workflow.
- Найдите строку и поле, которые указаны в warning.
- Исправьте значение в `catalog-public.xlsx` (или добавьте отсутствующий файл в `images/`).
- Запустите workflow повторно.

## Что делать после генерации `js/products.js`

Если `js/products.js` изменился, workflow автоматически создаст commit в текущей ветке.

Дальше:

1. Проверьте diff.
2. Убедитесь, что карточки отображаются корректно.
3. Создайте/обновите Pull Request.
4. После ревью — сливайте изменения.
